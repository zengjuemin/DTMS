# TalkToFigma 设计规则指南

## 1. 基础概念

### 1.1 TalkToFigma 简介
- TalkToFigma 是一个通过自然语言与Figma交互的工具，允许设计师通过对话方式创建和修改设计
- 它使用AI技术理解设计意图，并将其转换为Figma操作
- 可以通过简单的对话完成复杂的设计任务，减少重复性工作

### 1.2 工作流程
1. **连接Figma文档**：启动TalkToFigma并连接到Figma文档
2. **发出设计指令**：通过自然语言描述设计需求
3. **AI执行操作**：AI理解指令并在Figma中执行相应操作
4. **审查和迭代**：检查设计结果，继续通过对话进行调整和完善

## 2. 设计系统规范

### 2.1 颜色系统
- **主色调**：
  ```
  主要品牌色: #4B6BFF
  次要品牌色: #7089FF
  ```
- **中性色**：
  ```
  黑色: #000000
  深灰: #333333
  中灰: #666666
  浅灰: #999999
  超浅灰: #CCCCCC
  白色: #FFFFFF
  ```
- **功能色**：
  ```
  成功: #52C41A
  警告: #FAAD14
  错误: #F5222D
  信息: #1890FF
  ```
- **颜色使用规则**：
  - 保持色彩一致性，不随意创建新颜色
  - 确保文本颜色与背景的对比度符合WCAG 2.1 AA级标准(最低4.5:1)
  - 为颜色创建语义化命名，避免使用"红色"、"蓝色"等直观命名

### 2.2 字体系统
- **字体家族**：
  ```
  中文: PingFang SC
  英文: SF Pro Display
  代码: SF Mono
  ```
- **字号等级**：
  ```
  特大标题: 36px
  大标题: 28px
  中标题: 24px
  小标题: 20px
  正文大: 16px
  正文标准: 14px
  正文小: 12px
  辅助文字: 12px/11px
  ```
- **字重规范**：
  ```
  特粗体: 800
  粗体: 600
  标准体: 400
  轻量体: 300
  ```
- **行高规范**：
  - 标题: 1.4 倍字号
  - 正文: 1.5 倍字号
  - 段落: 1.8 倍字号

### 2.3 间距系统
- 采用4px基础栅格系统设计间距
- **间距序列**：
  ```
  超小间距: 4px
  小间距: 8px
  中间距: 16px
  大间距: 24px
  超大间距: 32px
  特大间距: 48px
  巨大间距: 64px
  ```
- **间距使用规则**：
  - 组件内部元素使用小间距(4px/8px)
  - 组件之间使用中间距(16px/24px)
  - 区块之间使用大间距(32px/48px)
  - 遵循视觉层次和亲密性原则设置间距

### 2.4 阴影系统
```
轻量阴影: 0px 2px 4px rgba(0, 0, 0, 0.05)
标准阴影: 0px 4px 8px rgba(0, 0, 0, 0.08)
中度阴影: 0px 8px 16px rgba(0, 0, 0, 0.12)
强烈阴影: 0px 16px 24px rgba(0, 0, 0, 0.16)
```

### 2.5 圆角系统
```
无圆角: 0px
小圆角: 4px
标准圆角: 8px
中圆角: 12px
大圆角: 16px
全圆角: 9999px
```

## 3. 组件设计规范

### 3.1 按钮组件
- **类型**：主要按钮、次要按钮、文本按钮、图标按钮、危险按钮
- **状态**：默认、悬浮、点击、禁用、加载中
- **尺寸**：大(高48px)、中(高40px)、小(高32px)、迷你(高24px)
- **设计要点**：
  - 主要按钮使用品牌色填充
  - 按钮文本居中，左右内边距为字号的2倍
  - 图标按钮在不同尺寸下保持图标清晰可辨
  - 禁用状态透明度为40%
  - 按钮文本使用粗体增强可点击感

### 3.2 输入框组件
- **类型**：单行输入、多行输入、密码输入、带前/后缀输入
- **状态**：默认、焦点、填充、错误、禁用
- **尺寸**：大(高44px)、中(高36px)、小(高28px)
- **设计要点**：
  - 边框使用中性色系，获取焦点时边框变为品牌色
  - 错误状态使用错误色突出显示
  - 输入框内文本垂直居中
  - 内边距左右保持16px
  - 多行输入框高度随内容自适应

### 3.3 导航组件
- **类型**：顶部导航、侧边导航、标签页导航、面包屑导航
- **状态**：默认、激活、悬浮
- **设计要点**：
  - 导航项保持足够的点击区域(最小44px高)
  - 激活状态使用品牌色或加粗样式突出显示
  - 导航层级不超过三级
  - 遵循用户阅读顺序和使用频率排列导航项

### 3.4 表单组件
- **布局规则**：
  - 标签对齐方式：左对齐、右对齐、顶对齐
  - 表单项间距保持一致，建议使用24px
  - 必填项使用红色星号(*)标记
  - 错误提示紧随表单控件之后
- **验证规则**：
  - 实时验证为优先，提交验证为辅助
  - 错误信息明确指出问题和解决方法
  - 成功状态给予明确的视觉反馈

### 3.5 表格组件
- **设计要点**：
  - 列宽根据内容设置，避免内容被截断
  - 表头使用浅色背景与内容区分
  - 交替行使用不同背景色提高可读性
  - 可操作列放置在表格最右侧
  - 使用合适的文本截断或提示展示过长内容

## 4. TalkToFigma 操作规范

### 4.1 通用命令规范
- 使用简洁明了的自然语言描述设计意图
- 指定明确的尺寸、颜色、位置等参数
- 操作多个对象时清晰指明对象名称或ID
- 创建组件时使用语义化命名，以便后续引用

### 4.2 创建对象命令
- **基础形状创建**：
  ```
  "创建一个宽200px高100px的矩形"
  "在坐标(100,100)处添加一个50px的圆形"
  "绘制一条从(0,0)到(200,200)的直线"
  ```
- **文本创建**：
  ```
  "添加一个标题文本'产品功能'，字号24px"
  "创建段落文本，内容为'这是一段描述文字'，宽度300px"
  ```
- **组件创建**：
  ```
  "创建一个主要按钮，文本为'提交'"
  "添加一个带搜索图标的输入框"
  "创建一个带标题和描述的卡片组件"
  ```

### 4.3 编辑对象命令
- **属性修改**：
  ```
  "将矩形的填充色改为#4B6BFF"
  "设置文本的字体为PingFang SC"
  "调整按钮的圆角为8px"
  ```
- **位置调整**：
  ```
  "将矩形移动到坐标(200,300)"
  "把标题向右移动20px"
  "调整卡片组件的位置到页面中央"
  ```
- **组对象操作**：
  ```
  "选择所有按钮并水平对齐"
  "将这三个图标垂直等间距排列"
  "把标题和描述组合成一个组"
  ```

### 4.4 样式操作命令
- **颜色样式**：
  ```
  "创建名为'primary'的颜色样式，值为#4B6BFF"
  "应用'primary'颜色样式到所有按钮"
  ```
- **文本样式**：
  ```
  "创建名为'heading-1'的文本样式，字号28px，字重600"
  "将'heading-1'样式应用到页面所有标题"
  ```
- **效果样式**：
  ```
  "添加轻量阴影效果到卡片组件"
  "为按钮创建悬浮状态，增加中度阴影"
  ```

## 5. 设计协作规范

### 5.1 命名规范
- **页面命名**：
  - 使用"[类型]-[功能]"格式命名
  - 例如："设计规范-颜色系统"、"页面-登录"
- **图层命名**：
  - 图层名称应反映其功能或内容
  - 使用前缀标识图层类型，如"btn-"表示按钮
  - 保持统一的命名风格，便于团队理解
- **组件命名**：
  - 使用"[类别]/[名称]/[变体]"格式
  - 例如："Button/Primary/Large"、"Input/Search/Disabled"

### 5.2 组织结构规范
- **图层组织**：
  - 相关元素应组合为组或框架
  - 保持图层面板整洁，使用合理的层级结构
  - 遵循自上而下的视觉顺序排列图层
- **组件组织**：
  - 按功能或类型分类组件
  - 创建清晰的组件变体，避免重复创建相似组件
  - 使用组件说明描述用途和使用方法

### 5.3 版本控制规范
- 使用有意义的版本命名，包含日期和版本号
- 在主要更新前创建分支
- 记录重要修改的说明，便于团队理解变更
- 定期整理和归档旧版本文件

## 6. TalkToFigma 最佳实践

### 6.1 设计流程优化
- **使用场景**：
  - 快速原型创建
  - 设计系统维护
  - 批量样式调整
  - 排版规范化
- **技巧**：
  - 从整体到局部，先布局后细节
  - 使用命令组合完成复杂操作
  - 利用AI理解语境，连续对话完成设计

### 6.2 常见问题与解决方案
- **命令不被理解**：
  - 使用更清晰、具体的描述
  - 分解复杂命令为多个简单步骤
  - 提供视觉参考或实例说明
- **设计不一致**：
  - 建立并引用设计系统组件
  - 使用共享样式保持一致性
  - 定期审查设计保持对齐

### 6.3 效率提升建议
- 创建并使用命令模板，减少重复输入
- 掌握TalkToFigma快捷命令和简写方式
- 建立个人常用操作库，方便快速调用
- 结合键盘快捷键和语音命令混合操作
